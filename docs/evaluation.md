# Classification evaluation

Generated by `python -m app.cli evaluate` on 2026-11-28 with `openai/gpt-oss-120b`, `openai/gpt-oss-20b`. 41 resources: the 15 in the simulated estate and 26 hard variants from `backend/app/seed/variants.py`, which are generated in memory and never deployed. Each model judged every resource once, so a rerun can differ slightly. The Validator history section at the end is written by hand and kept when the report is regenerated.

- **rules**: the deterministic classifier alone.
- **llm**: one LLM call per resource with its masked, truncated code and config, unchecked.
- **hybrid**: the rules when they are confident; otherwise the LLM's verdict if it passes the validator (every quote must appear in what the LLM was shown), else the rules. Models and tools a verdict names that are not in the collected data are dropped, never stored.

## Where the models ran

The models were called through Groq's API, outside AWS. Bedrock stays the crawler's default so that a real account's code and config never leave AWS. This evaluation ran elsewhere because of where models could be called when it was written: on Bedrock, the AWS test account got "not available for this account" for Anthropic models and had every Nova quota (requests and tokens per minute, tokens per day) at 0; on the Gemini API free tier, Flash allowed 20 requests a day against the 41 one model needs, and Pro allowed none. The Bedrock and Gemini clients stay in the code. On Groq, the Llama models (llama-3.3-70b-versatile, llama-3.1-8b-instant) returned model_not_found for this key, so gpt-oss-20b is the small, fast model and gpt-oss-120b stands in for a 70B-class one. Only synthetic code and config were sent: the simulated estate's seeded functions and the generated variants, with secrets masked as in a real crawl. No real account's resources were sent.

## Validator history

Written by hand. `cli evaluate` keeps this section when it regenerates the report above.

### What changed in v2, and why

Validator v1 had a bug. It checked evidence quotes against the collected data, but not against the text the LLM was actually shown. `hybrid.context()` shows the model the same data, but it adds labels such as `env:` and `iam actions:`, indents them, and clips long code. v1 also compared each quote exactly as the model wrote it. So it rejected quotes that were faithful to what the model saw:

- quotes that kept a label from the shown text, such as `iam actions:\n  comprehend:DetectSentiment`;
- quotes the model wrapped in quotation marks or JSON-escaped, such as `"comprehend = boto3.client(\"comprehend\")"`.

In v1, a single model or tool name missing from the collected data also rejected the whole verdict. "Textract", for example, is a service name, not a string in the code.

Validator v2 makes three changes:

- **Quotes are matched against the exact text the LLM was shown.** Whitespace is still collapsed. Each quote is also tried after stripping one layer of surrounding quotes and JSON escapes, and after removing a leading `label:` that appears in the shown text.
- **Ungrounded names are dropped, not fatal.** Models and tools missing from the collected data are recorded in `llm_verdict.rejected_items`, and the verdict is judged on the rest.
- **Ungrounded names are never stored.** They never become the system's models or tools in the registry, even when the verdict is rejected.

These are unchanged:
- the prompts, the variants and the confidence thresholds;
- the 0.05 model choice rule;
- every other check: true or false fields, a known category that agrees with `is_agent`, an agent must be AI, and an AI verdict needs a quote.

Quotes still have to be verbatim. v2 still rejects paraphrases, elisions such as `assistants.create(...)`, and misquotes such as a wrong model version. One side effect: a quote from code beyond the 6,000-character clip now fails, because the model never saw it.

The hybrid decisions table above shows what v2 still rejects:
- a misquoted model version: `...-v0:0` where the code says `...-v1:0`;
- a fragment that is not in the code: `"tool_calls":`;
- quotes that remove line breaks and indentation instead of collapsing them. For example, `{"name": "web_search"` where the code breaks the line after `{`. This is most likely also what happened to the cut-off `assistants.create(` and `urllib.request.Request(` quotes, since the shown text breaks the line right where they are cut off.

Three resources had no verdict from gpt-oss-20b at all, and those count as rejected too.
